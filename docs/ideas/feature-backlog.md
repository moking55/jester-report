# Feature backlog (หลัง v1.7.0)

รวบรวม 20 พ.ย. 2026 จาก CAPABILITY_MAP.md และหัวข้อ "Out of scope / ไม่ทำ" ของทุก SPEC ตัดสิ่งที่ทำแล้วออก
(designer ลากวาง, rate limit ต่อ API key, อัปโหลดรูป) — ยังไม่ได้ไล่อ่านโค้ดทุกจุด บางข้ออาจมีบางส่วนแล้ว
เก็บไว้เลือกทำทีหลัง: เลือกข้อแล้วเริ่มด้วย interview → spec → plan ตามปกติ

## เอกสารและการออกเอกสาร

- เลขรันเอกสารอัตโนมัติ (ตัดออกจากแผน v1.4/v1.5)
- ล็อกเอกสารที่ออกแล้วไม่ให้แก้หรือลบ (หลักฐาน), ลบทีละใบ, อายุเก็บแยกจากประวัติ render
- API ให้ระบบอื่นดึงเอกสารที่ออกแล้วด้วย API key
- PDF/A, PDF/UA และลายเซ็นดิจิทัล
- Export เป็น XLSX / DOCX
- Render หลายใบรวมเป็น zip ในคำขอเดียว

## การจัดหน้า (designer / template) — เลือกทำแล้ว 20 พ.ย. 2026 (v1.8)

- กระดาษขนาดอื่นนอกจาก A4 (A5, Letter, ใบเสร็จความร้อน)
- แก้ header/footer ใน designer (ตอนนี้แสดงอย่างเดียว)
- วางตามพิกัด (absolute positioning)
- ตารางซ้อนตาราง / list ซ้อนเกิน 1 ระดับ

ตัดออกจาก backlog (ผู้ใช้ 20 พ.ย.): page subtotal, group-by แบบบล็อก, กลุ่มที่ไม่มีข้อมูล, กราฟ, แก้ class/`report.css` จาก designer,
แปลง JRXML ตรง, formatter ภาษาอังกฤษ

## ฟอร์มออกเอกสาร

- ช่องโชว์/ซ่อนตามเงื่อนไข
- ช่องคำนวณในฟอร์ม
- แนบรูป/ไฟล์ตอนกรอกฟอร์ม
- ให้หัวหน้าทีมจัดฟอร์มหรือใช้ designer เอง (ตอนนี้เป็นงาน dev)

## ผู้ใช้และสิทธิ์

- Role/RBAC (แยกคนออกแบบกับคนออกเอกสาร)
- SSO/OIDC, 2FA
- อีเมลเชิญผู้ใช้ / รีเซ็ตรหัสผ่านทางอีเมล
- จำกัด API key ราย template (ตอนนี้มี allow-list)
- Audit log ละเอียด
- Multi-tenant

## การทำงานร่วมกันและประวัติ

- ประวัติ revision ของ draft ย้อนดู/กู้คืน (ตอนนี้มีแค่ version ที่ publish)
- หลายคนแก้ draft เดียวกันแบบ real-time

## การ render และการต่อระบบ

- Render แบบ async: job queue, webhook, ตั้งเวลา, ส่งอีเมล
- Retry อัตโนมัติเมื่อ render ล้มเหลว
- Data connector ดึงข้อมูลจากฐานข้อมูล/ระบบอื่นตรง
- Metrics/Prometheus

## ระบบและการดูแล

- Backup อัตโนมัติตามเวลา + ลบ backup เก่า (ตอนนี้มีแค่ตัวอย่าง cron ใน README)
- เข้ารหัส backup และส่งขึ้น cloud
- Point-in-time recovery
- Kubernetes/Helm, CLI

## Studio

- Mobile layout
- UI หลายภาษา (ตอนนี้ไทยอย่างเดียว)
